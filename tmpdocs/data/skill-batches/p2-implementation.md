## 2. 机制实现

### 2.1 连击数（用户核心规则）
- `SkillEffect.hits` = 显式「N连击」；`combo_eligible` = desc **含有「连击」**。
- **只有** `combo_eligible` 的技能受连击数buff加成：`effective_hits = max(1, int((hits + flat) × (1 + 0.10 × pct)))`。
  - 常规连击数buff 1 层 = +1 连击（热身运动 +3 → 3 层）；pct 1 层 = +10%（暴风眼 +100% → 10 层 → 翻倍）。
  - 纯伤害技能（无连击描述）**不被**加成（测试钉死：热身运动 +3 对撞击无效）。
- 连击数buff 存于 `Unit.stat_mods`（`stat="combo"`），随离场清除、可被常规驱散（与 S1 特性增益区分）。
- 连击伤害：`resolve_skill` 逐发 `compute_damage`+`apply_hp_loss`+damage 事件（带 `hit/hits`），**途中目标阵亡即停**（连击不落在尸体上）。
- 虫鸣：基础连击 = 1 + 队内（含自己）携带该技能的单位数。

### 2.2 先手（用户核心规则）
- `先手+N` → `Skill.priority = N`（常规技能 0；俯冲/先发制人 +1、后发制人 -1）。
- 队列排序**先比 priority、再比 speed**（`build_queue` 按 `(-priority, -speed)`）——已有机制，P2 只需把先手落进 `Skill.priority`。测试钉死：先手+1 慢速胜普通快速；先手-1 快速反落后；同优先级再比速度。

### 2.3 每连击状态（花炮 / 冰捆缚）
- 状态系 `stat_effects` 在 `hits` 次连击里**每连击应用一次**（叠层）。
  - 花炮：2连击 × 魔攻+60% → 合计 +120%。
  - 冰捆缚：2连击 × 敌方全技能能耗+1 → 敌能耗 +2（`EnergyCostMod` 层 -2）。
- 非连击状态（缓一缓）`hits=1` 应用一次。

### 2.4 资源效果
- 能量：伤害后 `self_energy_gain` / 状态后 `energy_gain`；场下 `bench_energy_gain`（自己队伍后备）；勾魂 `steal_energy`（敌方 -N、自己 +N）。
- 回血：`heal_pct_self`（休息回复 30% / 丰收 20% / 根吸收 15% / 缓一缓 10%）。
- 吸血：本次 `lifesteal_pct`；贪婪 = 持久 `lifesteal` buff（1 层 = 100%），之后每次攻击都吸血。

## 5. 实现中做的主（可复核）语义判断

1. **连击数buff只加成「带有连击描述」的技能**（含显式 1连击，如落石/音波弹）；纯伤害技能不受加成——严格按负责人字面规则。
2. **连击数buff 夹到 ≥1**：敌连击 -4 不会让 1连击技能变 0 连击（技能至少打一下）。
3. **场下回能量**（富养化/养分回流）作用于**自己队伍**的后备（技能是自队增益）；若应作用于双方场下需改。
4. **虫鸣**的连击数含使用者自己（队内携带数含自己）。
5. **连击数buff 与 特性增益同存于 stat_mods**（`trait` 字段区分），特性连击 buff 以特性描述为准（P2 无此类特性）。
