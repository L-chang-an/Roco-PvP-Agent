## 3. 十大聚类与共性

按「机制共性」把 553 条聚成 A–J 十类：

### A. 伤害类（345 攻击技）
- A1 纯伤害：110 条，`造成物伤/魔伤`——引擎已支持。
- A2 伤害 + 资源：`自己回复1能量`、`回合结束能耗永久-1`（抓挠系就是 A2）。
- A3 伤害 + 连击：`N连击`（61 条）。应对状态下连击数翻倍是常见变体。
- A4 伤害 + 威力条件修正：`每使用1次，威力永久+X`、`敌方能量≤2时5倍`、`每失去5%生命威力+X`。
- A5 伤害 + 应对修正：`应对状态：威力变3倍`（130 应对里的攻击侧）。
- A6 伤害 + 附加效果：`敌方获得X层灼烧`、`吸血`、`驱散`、`打断`、`脱离`。
- A7 伤害 + 永久成长：`威力永久+X`、`连击数永久+X`、`能耗永久-X`。

### B. 属性增减益（57+ 条，另有敌方减益 79）
- 维度：物攻/魔攻/物防/魔防/速度/双攻/双防/生命。
- 模式：pct%（+70% 等）或 flat（+80、-60）。
- 目标：自己 / 敌方。
- 常见修饰：`持续3回合`（**有持续时间**）、`应对防御时更强`（应对条件）。

### C. 资源（能量）类（58+27）
- `回复 N 能量`、`能耗+N`（全技能/单技能）、`能量≤N 时条件`。
- E0b 已有 `recharge` / `self_energy_gain` / `energy_cost`——这是最容易接的一部分。

### D. 印记类（40 条，~15 种）
- 统一形状：`获得 N 层X印记`，可叠层（驱散按层、回合末/被攻击时按层结算）。
- 用途：攻击印记（增幅）、棘刺印记（反伤）、光合/湿润（条件强化）、星陨/暗涌（结算伤害）、减速（减益）。
- 代表：`主场优势`＝自己获 1 层攻击印记；`焚烧烙印`＝驱散双方印记并转化为灼烧。

### E. 异常状态类（非属性增减益）
- 持续伤害：灼烧/中毒/冰冻（回合末按层扣血）。
- 行动/换人封锁：眩晕（跳过行动）、禁足（禁换人）。
- 特殊：寄生（吸血式持续）、萌化（可叠层的减益异常）、湿润、棘刺（反伤）。
- 共性：**可叠层 + 通常带持续时间 + 回合末或特定时机结算**。

### F. 场地级状态（天气，8 条）
- `将天气改为雨天，持续8回合`（雨/沙暴/暴风雪/雷鸣 4 种）。
- 影响：`天气为雨天时，本技能能耗-2`、`技能系别和天气系别相同`、`天气为沙暴时先手+1`。
- 共性：**场地级持久状态，独立于单只精灵，全局生效，带持续时间**。

### G. 位置 / 换人 / 传动（14+13 条）
- 脱离：`自己脱离`（退场换人）、`敌方脱离`、`回合结束返场`（离场后回场）。
- 入场/返场触发：`替换入场的精灵回复8能量`、`每次入场，威力永久+40`、`使敌方精灵返场`。
- 传动（机械系专属）：`位于1号位时威力+60`、`传动1`——技能位置影响效果，且技能位置可被传动/交换。

### H. 事件触发类（用户点名的核心）
| 触发器 | 条数 | 例子 |
|---|---|---|
| 应对成功时 | 130 | `应对状态：本次技能威力变为3倍` |
| 入场/出场时 | 4+5 | `每次入场，本技能威力永久+40`；`自己脱离，替换入场的精灵回复8能量` |
| 回合结束时 | 8 | `回合结束自己返场`；`造成物伤，回合结束时，本技能能耗永久-1` |
| 击杀/击败后 | 6 | `若使用本技能击败敌方，回复6能量`；`每次击败敌方，威力永久+75` |
| 受到攻击时 | 5 | `若蓄力期间受到攻击，威力变为敌方技能威力的3倍` |
| 使用本技能后 | 19 | `每次使用后，本技能连击数永久+1` |
| 下一回合/下次 | 12 | `下一次攻击时，技能威力+70` |
| 蓄力后 | 9 | `蓄力，造成物伤`（两阶段） |

### I. 决策点类（选择，19 条）
- `选择：驱散敌方所有增益或驱散双方1层印记`、`选择：自己回复25%生命或回复8能量`。
- 共性：**回合内一个额外决策点**——与 E0b 已实现的「阵亡交互式补位」是同一类机制。

### J. 特殊机制
- 巧变（11）：`巧变：火系攻击技能`——技能可化为其他系别/技能（影响克制/能耗/应对）。
- 吸血（10）、先手（10）、打断（8）、冷却（3）、复制/借用（3）、蓄力（9）。

## 4. 共性提炼：效果分解公式

443 条带效果技能几乎都能分解成统一四元组：

> **Effect = (Trigger, Target, Modifier, Params)**
> 技能 = 一个基础行为（攻击/状态/防御）+ 若干条 Effect

| 槽位 | 取值 |
|---|---|
| **Trigger**（触发时机） | 立即（随技能结算）· 应对成功时 · 入场时 · 回合开始时 · 回合结束时 · 击杀后 · 受到攻击时 · 使用本技能后 · 下一回合 · 蓄力释放时 · 每使用 N 次 |
| **Target**（作用目标） | 自己 · 敌方在场 · 场下所有 · 双方 · 天气/场地 · 技能本身 · 即将替换入场的精灵 |
| **Modifier**（作用方式） | 伤害×N连击 · 威力± · 能耗± · 能量回复 · 属性(维度,模式,值) · 印记(N层,类型) · 异常(类型,层) · 生命回复% · 驱散(增益/印记/减益) · 脱离/返场/换人 · 天气(类型,持续) · 吸血 · 先手± · 打断 · 蓄力标记 |
| **Params**（参数） | 数值、层数、持续时间（`持续N回合`/`永久`/`本回合`/`本次`）、条件（`若…`） |

**两条最重要的共性**：
1. **技能 = 基础行为 + 多条 Effect**，Effect 之间相互独立、可组合。
2. **触发器是横切面**——130 条「应对」、8 条「回合末」、6 条「击杀后」等，本质是同一套事件钩子被不同技能挂在不同时机。**做一套事件钩子系统，就同时覆盖 130 条应对 + 全部事件触发技能**。

## 5. 逐个机制的实现思路（对照现有 E0b 架构）

现有引擎缝（可复用的锚点）：roster spec ↔ `build_unit`、事件系统 `ev()`、优先级队列、交互式 session（已支持阵亡补位决策点）、纯函数 `compute_damage`、`end_of_turn` 扩展点。

| 机制 | 实现思路 | 架构增量 |
|---|---|---|
| 纯伤害 / A2 资源 | 现有 `compute_damage` + `self_energy_gain` | 无 |
| 连击（A3） | `resolve_skill` 里按 hits 循环 `compute_damage`+`apply_hp_loss`，逐发发事件；每发后查 faint | 伤害管线加 hits 循环 |
| 威力条件/永久（A4/A7） | 技能从「共享静态定义」改成「每单位一份可变实例」，威力/能耗/连击数是实例字段 | **SkillInstance**（可变）替代共享 SkillDef |
| 应对修正（A5） | 现有 `counter_vs`/`counter_damage_mult` 扩展到 `counter_extra_*` 任意效果 | 应对钩子 |
| 附加效果（A6） | 伤害结算后追加 Effect 列表 | Effect 列表 |
| 属性增减益（B） | 现有 `stat_mods`（pct/flat 层）**补 duration 字段**，`aggregate_stats` 已支持 | stat_mod 加 duration + 回合末递减 |
| 能量（C） | 现有 energy 体系 | 无 |
| 印记（D） | Unit 加 `marks: dict[类型, 层数]`；攻击/棘刺/结算类在伤害钩子读 | **marks 目录 + 伤害钩子** |
| 异常状态（E） | Unit 加 `statuses: dict[类型, 层数+剩余回合]`；回合末 tick 结算灼烧/中毒；眩晕/禁足在行动门控读 | **statuses 目录 + 回合末 tick + 行动门控** |
| 天气（F） | BattleState 加场地级 `weather`（类型+剩余回合）；`end_of_turn` 递减 | **FieldState** |
| 脱离/返场/换人（G） | 效果触发交换 = 复用 `apply_replacement`/`resolve_switch` 的换人原语 + 入场/离场钩子 | **on_enter/on_exit 钩子** |
| 事件触发（H） | **统一事件钩子分发器**：turn_start / enter / exit / deal_damage / take_damage / ko / counter / turn_end | **hook 系统**（核心） |
| 选择（I） | 泛化交互式 session 的决策点协议（与阵亡补位同一机制） | 决策点协议 |
| 巧变/传动/蓄力（J） | 巧变=skill 系别动态化；传动=技能位置状态+移动；蓄力=Unit 蓄力标记+释放回合 | 技能位置状态、蓄力标记 |

## 6. 架构重构评估：**需要重构，但是增量式，锚点不换**

**必须新增的四大件**：

1. **效果模型**：`SkillDef`（静态定义）→ 携带「效果表」；`SkillInstance`（每单位可变副本）承载永久成长（威力/能耗/连击数）。效果表不是 553 条手写大函数，而是**结构化的 Effect 列表**（复用第 4 节四元组），按共性模板批量生成（如 `造成物伤+自身能量+1` 一个模板管几十条）。
2. **事件钩子系统**：引擎关键点（回合开始/回合结束/入场/离场/造成伤害/受到伤害/击杀/应对/使用技能）统一发事件 → 每个在场单位（技能 + 特性）挂的钩子被调度。**这是 130 条应对 + 全部事件触发的共同底座**。
3. **状态目录**：`marks`（~15 种印记）、`statuses`（灼烧/中毒/冰冻/眩晕/禁足…）、`weather`（4 种场地）、`durations`（持续 N 回合）——全部落在 `BattleState`/`Unit` 的新字段，随 `to_dict`/`from_dict` 序列化（马尔可夫性测试继续成立）。
4. **决策点协议**：把已实现的「阵亡补位交互」抽象成通用决策点（19 条「选择：A或B」+ 换人），session 的 `_need_replace` 泛化成 `_pending_decision`。

**必须保持不动**：
- roster spec ↔ `build_unit` 的缝（引擎测试不用改）。
- `compute_damage` 纯函数 + 显式入参（继续表驱动单测）。
- 事件系统 `ev()` 形状。
- 优先级队列与「阵亡即回合结束、交互式补位」。
- `state.turn += 1` 唯一推进点（`end_of_turn` 变成真正做事的地方：tick 灼烧/中毒/印记/天气 duration 递减）。

**不建议**：解析中文 desc 做 DSL 编译器。`desc` 是自由文本（同一机制十几种写法），编译器脆弱且不可测。正确做法是**结构化效果表**（像 E0_EFFECTS 一样手写、但按共性模板覆盖 553 条），desc 只做展示。

## 7. 分阶段路线图

- **P1 效果模型 + 钩子系统 + 状态目录**：效果表骨架、SkillInstance、hook 分发器、marks/statuses/weather 字段 + 序列化 + 马尔可夫性保持。这一层落地后，纯伤害/连击/属性增减益/能量/印记/天气/事件触发的大多数就能逐条挂上。
- **P2 按聚类批量实现**：连击与附加效果 → 印记 → 异常状态 tick → 天气 → 脱离/返场。
- **P3 决策点与特殊机制**：选择 A/B → 巧变 → 传动 → 蓄力。
- **P4 特性系统**：与技能共用钩子，见特性分析文档。

每阶段以「可对战白名单覆盖率」为可见指标（当前 443/553 带效果，逐阶段把可表达比例顶上）。

## 8. 技能实现排序表（分批实现路线）

原则：**先实现一批、测试一批、再进入下一批**；每一批都能独立提交、独立验收（以「可对战白名单覆盖率」为可见指标）。批次按「类别 + 难易度 + 依赖关系」排，后一批只依赖前一批的基建，不回头改前一批的形状。
