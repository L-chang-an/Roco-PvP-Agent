## 1. 设计原则（表达力边界）

**两个正交维度**：

```
维度A：Hook 时机（什么时候触发）
   事件钩子（副作用，可追加/取消原子）：TURN_START / TURN_END / ENTER / EXIT
      / SKILL_RESOLVE / DEAL_DAMAGE / TAKE_DAMAGE / KO / COUNTER / MARK_TRIGGER(新)
   读钩子（数值修正，无副作用）：STAT_CALC / SKILL_COST / ATTACK_POWER

维度B：效果动作（触发后做什么）
   ① 即时效果原语（直接改状态）：stat_mod / energy_gain / energy_cost_mod / heal_pct
      / dispel_gains / mark_add / mark_consume / set_field_state（天气，新）
   ② 追加原子（进队列后续执行）：BONUS_ATTACK（反击/追加攻击）/ BONUS_SKILL（追加技能效果）
      / 复用 SWITCH_OUT·SWITCH_IN·DEATH_IN
   ③ 取消原子（打断）：interrupt（取消队列中指定原子）
```

**映射规则**：
- 一个技能/特性效果 = **一个 Hook 时机**（或读钩子修正）**+ 若干即时效果 + 可选追加/取消原子**；
- 效果**默认表达为即时**，只有"需要等到将来某个时机再结算"（反击、追加攻击、下回合眩晕、打断被应对技能）才用**追加/取消原子**；
- 读钩子（在场时气场/携带系别修正）**不改状态、不追加原子**，只返回修正值参与结算。

## 4. 需要的新基础设施（核心贡献，按依赖排序）

### 4.1 `SkillMods`（单位级技能修改器）—— 最高优先
覆盖：威力永久+N、能耗永久±N、连击数永久+N、技能替换（愿力冲击）、能耗永久-N。
```python
@dataclass
class SkillMod:
    slot: int                  # 技能槽位（-1 = 全技能）
    power_delta: int = 0
    energy_cost_delta: int = 0
    hits_delta: int = 0
    replaced_with: str = ""    # 替换为的技能名（愿力冲击）
# Unit.skill_mods: list[SkillMod]（回合间持久，进 to_dict！）
```
- 读点：`effective_skill(unit, slot)`（apply power/energy/hits/replace 后返回派生 Skill）——`compute_damage`/`skill_energy_cost`/`effective_hits` 都改读它；
- **必须进 `to_dict/from_dict`**（持久、跨回合）→ 触及 state_hash，但只加字段，旧快照 `from_dict` 容错。

### 4.2 `Marks`（印记系统）—— 高优先
覆盖：~20 种印记（星陨/棘刺/萌化/中毒/攻击/湿润/减速/萌芽/寄生/光合/蓄势/龙噬/蓄电/风起/降灵/暗涌/灼烧…）+ 驱散/转化/层数限制。
```python
# Unit.marks: dict[str, int]（印记名 → 层数）
# 标记语义（类型注册表 MARK_CATALOG）：
#   每层效果 / 触发时机（星陨=技能命中时消耗）/ 上限（萌化可无限）/ 转化规则
```
- 结算点：`mark_add(unit, name, layers)` / `mark_consume(unit, name, n)`；
- 触发点：`MARK_TRIGGER` hook（守望星改消耗规则、无忧无虑改上限）。

### 4.3 `Interrupt`（打断/取消原子）—— 高优先
覆盖：应对成功额外打断（54 技能）、硬门（应对攻击打断并反击）。
- `emit` 返回值扩展：除"追加原子"外可返回"**取消目标**"（如 `interrupt_atom(kind=MAIN_SKILL, side=对面)`）；
- 调度器：从对方队列移除**第一条匹配的未执行 MAIN_SKILL 原子**（被打断的技能不再结算，发 `skipped(reason=被打断)` 事件）；
- **这正是原子队列设计的杀手级能力**——现引擎无法表达"打断已入队动作"。

### 4.4 控制状态（眩晕/寄生）—— 中优先
- 眩晕：`Unit.stunned`（下回合 MAIN_SKILL 原子被跳过，`TURN_START` 清除）；
- 寄生：按回合 tick 扣血（`TURN_END` 或专属 `POISON_TICK`）。

### 4.5 读钩子接线（STAT_CALC / SKILL_COST / ATTACK_POWER）—— 高优先
覆盖：在场时气场（7）、携带系别（24）、能量相关（11）、种族加成（13）。
- 语义：`collect_modifiers(state, unit, value_kind) -> 修正列表` → 汇总进 `compute_damage` / `skill_energy_cost` / `aggregate_stats`；
- **区分事件钩子（追加/取消原子）与读钩子（数值修正）**是本次设计的关键架构决策。

### 4.6 `BONUS_*` 追加原子（反击/追加攻击）—— 中优先
覆盖：刺肤反击（受到攻击后追加 50 威力物伤）、硬门反击。
- `AtomicActionSpec(kind=BONUS_ATTACK, receptor=攻击者)` → 追加到对方队列尾/头；
- 需要 §3.2 的 `source_guard` 防"反击→被打→再反击"死循环（决策 6）。

### 4.7 先手判定 ctx + 场状态（天气）—— 中/P2
- 先手判定：`build_turn_context` 已算出队列顺序 → 注入 ctx（`ctx.acted_first` / `ctx.foe_faster`）；
- 天气：`BattleState.field: dict`（**唯一新增的回合间状态**，触及 state_hash/数据契约，P2 单独拍板）。

### 4.8 计数状态（每N次）—— 中优先
- `Unit.counters: dict[str, int]`（如"已放地系技能次数""已回复能量"）+ 对应 hook 时机累计。

## 6. 与主重构方案（`refactor-atomic-action-queue.md`）的衔接

- **本映射是主重构 Phase 3（"填充真实特性/技能到新 hook 时机"）的数据蓝图**；
- 主重构 Phase 1（原子队列 + ENTER/EXIT 接线）是**本方案所有"新接 Hook"的物理前提**；
- 关键协同：
  - **打断 = 取消原子**（§4.3）只能建在原子队列之上——这是主重构相对现引擎的**不可替代收益**；
  - **反击 = 追加原子**（§4.6）同理；
  - SkillMods/Marks/计数是 Unit/BattleState 新增持久字段——需与主重构 §3 的"回合内不落 state"不变量对齐（SkillMods/Marks 是回合间持久，进 to_dict；队列仍是回合内局部）。
- **决策点联动**：主重构 §11 决策 6（追加原子调度键）直接影响反击/打断的插入位置（反击应"立即结算"→ 追加原子 priority 高）；决策 7（追加效果迷雾）直接影响 BONUS_ATTACK 的事件过滤。

## 7. 待确认/未覆盖模式（需负责人拍板或标注"游戏规则需确认"）
