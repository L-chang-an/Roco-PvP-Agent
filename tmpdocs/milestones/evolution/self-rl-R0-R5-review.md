## 〇、一句话主线（先立住）

**冻结的模型是先验，变强的是围绕它的四件外挂。** 闭源 LLM 权重动不了，所以"变强"全部沉淀在模型之外、可版本化、可回滚的工件里：战术手册（Playbook）、情境记忆（Memory）、价值函数（V）、构筑/对手池。R0–R5 就是把这四件外挂，从"能测量"一路建到"能进化、能收敛"的完整闭环。

## 一、被面试者视角：R0–R5 我做了什么

我接手时，项目有一个**确定性、可重放、有迷雾隔离**的对战引擎（E 线），能跑人机/自博弈并落盘轨迹，但**打完的每一局都归零**——没有任何环节把对局转成下次决策可用的经验。我要回答的问题只有一句话：**让两个 LLM 在自博弈中不断变强，怎么实现。**

我按"先能测量、再能学习、最后能进化"的顺序，用七个里程碑（S0 + R0–R5）把它建完：

**S0 共享地基**：把 `data_digest`/`rules_digest` 数据指纹上提到共享层，并修掉一个 P0 迷雾泄漏。这是后面所有"跨版本隔离"的地基。

**R0 可观测度量**：造一把"量强弱的尺子"——局面特征 `situation_key`/`v_heuristic`/击杀线表、轨迹重放分析、配对评测（固定基准 + 双向先后手 + Wilson 95% CI）、Elo/α-rank 基架。**没有尺子，"变强"无从谈起。**

**R1 情境记忆**：MemRL 两阶段检索的记忆库。把每一回合的局面、动作、结果沉淀成可检索的知识碎片，按 `data_digest` 隔离版本。**（后补「记忆接线」里程碑：检索结果注入 `LLMPlayer.decide`，Q 值随采纳更新，真正"存了还用、用了还反馈"。）**

**R2 信度分配**：把"这局输了"归因到具体回合。三个信号取交集——校准偏差（LLM 预测 vs 实际）、价值落差（回合前后 V 差）、反事实回放（fork 状态 + 代理尾策略）。

**R3 反思与有界编辑**：双分析师（失败/成功各自独立提示）把关键回合卡片变成结构化编辑提案，有界（L_t=4）地应用到战术手册，带 `[PROTECTED]` 保护和逐条审计。

**R4 Pareto 池与门禁**：把编辑接进完整进化闭环——Pareto 候选池（保多样性）、两级门禁（宽门入池 / 严门晋级）、专职剥削者（测可利用性）、历史回归门（防策略循环）。

**R5 慢更新与收敛**：`[PROTECTED]` 固化/撤回、Meta Playbook（反哺反思器）、价值函数上线、D_test 汇报（只汇报不回流）。

**闭环跑通**：`evolve epoch` 一个命令，就能从"初始一本空手册"跑到"多版本手册 + Pareto 池 + 记忆库 + D_test 报告"，全程确定性、可复现、可审计。

## 三、项目 Review

### 3.1 解决什么问题

**核心问题**：给定一个冻结权重的 LLM 和一个确定性对战引擎，如何让"两个 LLM 打完的每一局都不再归零"——即把对战经验持续转成可复用的能力，让胜率**可测地**提升。

拆成三个子问题：
- **度量**：怎么可信地测"谁强、强多少"（对抗自博弈的虚假进步）。
- **归因**：怎么把稀疏的终局胜负归到"哪一步走错了"。
- **进化**：怎么把归因结论变成可验证、可回滚的策略改进，且不坍缩、不过拟合、不循环。

### 3.2 用什么方法

| 里程碑 | 方法 | 对应论文/思想 |
|---|---|---|
| S0 | 语义数据指纹（sha256 覆盖归一化数据 + families + evolution_chains） | 版本隔离 |
| R0 | 确定性局面特征 + 配对评测 + Wilson CI + α-rank | GEPA「可观测度量」 |
| R1 | 三元组记忆 + 两阶段检索（相似度门→效用重排，z-score 标准化）+ 只更新被采纳条目 | MemRL |
| R2 | 三信号信度分配（校准偏差★ / 价值落差 / 反事实回放） | 校准偏差 + 反事实 |
| R3 | 双分析师 + 有界编辑（L_t）+ JSON schema 校验 + 降级 | GEPA + SkillOpt |
| R4 | Pareto 池 + 两级门 + 专职剥削者 + 历史回归门（≥45%） | GEPA Alg.2 + SkillOpt 双游标 |
| R5 | 慢更新 `[PROTECTED]` + Meta Playbook + 档位 A 价值函数 + D_test 汇报 | SkillOpt 慢更新 |

### 3.3 为什么这样解决

**① 为什么先度量再进化**——自博弈最著名的失败模式是"每代打赢上一代，v10 打不过 v3"（非传递环）。没有冻结基准 + 带置信区间的度量，任何"提升"都是不可信的。

**② 为什么记忆/手册是"被动注入"不是"工具主动查"**——对战每回合只有一轮 LLM 调用是延迟底线；迷雾隔离需要确定性收口（注入什么由 harness 代码决定，不给 LLM 一个可能读穿敌方隐藏状态的口子）；注入安全（学出来的半可信数据必须标注"历史经验非当前局面"，不能当指令执行）。

**③ 为什么三信号取交集**——校准偏差最干净但依赖 LLM 主动给 prediction；价值落差覆盖广但粗糙（掉值≠错）；反事实精确但贵。便宜信号定位候选、贵信号确认，是成本最优。

**④ 为什么反事实用代理尾而非 LLM 尾**——换一个动作后状态发散，记录里的后续决策可能全非法；真实 LLM 尾每回合 2 次调用 × M=24 成本不可接受。代理尾确定性、便宜、逐位可复现，作为"一致的"信度信号足够（R7 才换 LLM 尾做成本换精度）。

**⑤ 为什么 Pareto 池而不是"选胜率最高"**——这个游戏有非传递性（攻击>状态>防御>攻击 + 18 系克制），单点最优会在环上打转。Pareto 前沿保留"不被任何单一策略全面压制"的多样性；宽门入池（在某实例上最优即可）+ 严门晋级（复合分严格超过）分离"多样性"和"质量"两个目标。

**⑥ 为什么 `data_digest` 贯穿始终**——"跨版本记忆不可信"：引擎/数据变了，同样的局面+动作是两个不同的局面。所有工件（记忆、手册、池）都锚定版本指纹，保证"改引擎后旧结论自动隔离，不污染新结论"。

### 3.4 尝试过的其他方案（对比）

| 方案 | 我为什么不选 / 何时会用 |
|---|---|
| **权重微调 / RLHF** | 闭源模型动不了，直接排除 |
| **给 LLM 一堆工具做 ReAct** | 每回合多跳 tool-call 成本翻倍 + 迷雾/注入安全失控，R3 已明确拒绝 |
| **单点最优选择（选胜率最高）** | 非传递游戏会循环，Pareto 池保留多样性 |
| **Elo 实时积分当主信号** | Elo 是传递性模型，会误判循环优势；α-rank 专门处理非传递 |
| **纯启发式记忆（不用 z-score）** | MemRL 消融显示去掉 z-score 遗忘率 0.041→0.073 |
| **记忆均匀广播 Q 更新** | 无归因依据，改成"只更新被检索且被采纳的条目" |
| **LLM 自评当奖励** | 铁律：模型永不担任裁判，奖励只来自确定性引擎的胜负事实 |

### 3.5 相比其他方案的优点

1. **确定性可复现**：除真实 LLM 外，整条管线（引擎 → 指纹 → 检索 → 反事实 → 门禁）同 seed 逐位复现，任何结论都能被独立重跑验证。
2. **离线可验**：`PlaybookPlayer`（手册 hash 成策略种子）让 R4 闭环无 key 也能跑通、Gate 可测；真实 LLM 只是换一个 Player 实现。
3. **诚实不虚报**：Wilson CI 拒绝"样本不足的强结论"；严门拒绝"平手晋级"；离线基线 3 步零晋级正是门禁严格的表现。
4. **信息隔离三层**：迷雾（对战玩家）、`[战术手册]` vs Meta Playbook（优化器 vs 执行器）、D_sel/D_test/D_tr 三集（评测防污染）。
5. **可审计可回滚**：每个工件带版本/指纹/来源，`edit_apply_report.jsonl` 逐条追溯到证据，`pool.json` 可续跑。

### 3.6 现有框架的不足（诚实）

1. ~~记忆没有真正接线到对战~~ ✅ **已修复**（记忆接线里程碑）：R1 建了检索，但 main 实现漏了 plan §七的 `[记忆]` 注入。现已补上——`LLMPlayer.decide` 检索 top-3 记忆注入 `[记忆]` 块（标注"历史经验非当前局面"），`apply_adoption` 做采纳判定 + Q 更新，形成「存→检索→注入→采纳→更新」闭环。
2. **离线基线不产生晋级**：确定性 `PlaybookPlayer` + 假反思 LLM 下，3 步全入池零晋级（champion 一直是 pb_v000）。闭环机制对，但**"真变强"只能在真实 LLM 对战（`--llm`）下验证**，而我还没跑过真实 LLM 的完整 epoch。
3. **反事实代理尾有偏**：RandomPlayer 代理 ≠ 真实 LLM，`delta_winrate` 是"一致但偏"的信号，绝对值不可尽信。
4. **价值函数档位 A 大概率降级**：`train_value_fn` 的 AUC 门 0.75 在少量轨迹上很可能不达标 → 退回 `v_heuristic`，档位 A 形同虚设。
5. **引擎保真度不够**：只实装 217/553 技能效果、特性多为白板，进化出的"最优策略"只是**当前简化引擎下**的最优，迁移到真实游戏会失真。
6. **成本未压到底**：全量门每次要打 60 实例 × 双向，SPRT 早停、对手用更便宜档位等 R8 成本旋钮还没接。
7. **评测集自身可能过拟合**：D_sel 冻结了，但 D_test 季度换血、re-baseline 的运营机制还没跑起来。

### 3.7 初步提升方案

1. ~~把记忆接线进玩家~~ ✅ **已完成**：`LLMPlayer.decide` 注入 `[记忆]` + `apply_adoption` 采纳判定 + Q 更新。
2. **跑真实 LLM 的完整 epoch**：用 `--llm` 跑 `evolve epoch --n 8`，验证"真变强"（D_test 单调不降 + 关慢更新可复现退化），这是核心闭环的最终验收。
3. **反事实尾升级**：R7 的 SMC（关键回合用 LLM 自身做尾策略）作为"成本换精度"的可选增强，与代理尾交叉验证。
4. **价值函数降级诊断**：若档位 A 长期降级，说明特征不够——可加对手已揭示技能数/克制关系得分等特征，或改用引擎重放回归目标（本项目独有的便宜 V）。
5. **引擎保真度推进**：按 P3–P6 技能批 / 特性批继续实装，`data_digest` 自动隔离旧结论，M/R 线无需重做。
6. **成本旋钮**：SPRT 早停、对手用更便宜档位、全量门实例动态子采样（GEPA 教训：大部分预算花在验证，必须压）。

## 五、一句话总结

**R0–R5 交付的不是"一个更强的 AI"，而是一台"让冻结的 LLM 在自博弈中可信地变强"的机器**：它先造了把能量强弱的尺子（R0），再把对局沉淀成知识（R1）、把胜负归因到动作（R2）、把归因变成有界编辑（R3）、把编辑放进保多样性的池并严格门禁（R4）、最后靠慢更新和 Meta 手册收敛（R5）。它诚实地承认"离线基线不晋级"——因为变强需要真实 LLM 在对战里读出更好的手册，而这正是这台机器要验证的下一步。
