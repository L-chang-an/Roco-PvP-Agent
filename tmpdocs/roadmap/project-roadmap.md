### 0.2 核心策略（五条，负责人拍板后执行）

1. **E 线引擎是冻结地基**：已审计（`docs/audit/04-findings.md`）确认「确定性 / 迷雾 / 重放 / 非法动作 / 属性边界」全部独立验证通过，签名冻结清单已列明。M、R 两线都在其上构建，**不再动引擎核心**。
2. **M、R 两线并行**：组队顾问（M）与自博弈进化（R）只共享「引擎 + 数据指纹」，互相不阻塞，可在阶段 0 内并行推进。
3. **R 线是「移植」不是「合并」**：`main` 的 R0–R8 代码作为参考实现，按当前 E 线数据（217 已实装技能 + 进化链/萌化/首领化字段）移植回来，先移植 R0–R3（进化核心闭环），R4–R8 留作阶段 2。
4. **「完美复刻」是独立渐进长线，不阻塞最小闭环**：引擎保真度（补全 553 技能效果、全部特性、状态/天气/道具/机制）按批推进，M/R 通过「数据指纹隔离 + 签名冻结接口」自动跟踪引擎变化，不会因为引擎没做完就卡住交付。
5. **组队建议对标「当前引擎」，不标榜对标「真实游戏环境」**：顾问每条建议锚定 `data_digest` 对应的引擎快照，只用 `validate_team`/`simulate_matchups` 在当前引擎上验证，绝不声称「真实环境最优」。因此**顾问的完善度与引擎保真度解耦**——ScopeGate、Skill、回答评测集这些「安全/可追溯/可测/可扩展」能力，最小闭环阶段就该做齐；引擎逐批逼近真实后，同一套建议自动变「更真」。

### 0.3 最小闭环（阶段 0）的定义

三线各自端到端跑通一次完整演示：

- **E 线**：人 vs AI（随机/真实 AI）+ AI vs AI 对战 → 轨迹落盘 → 不改引擎完美重放、改引擎后 AI 能从轨迹分析经验（补 AUD-E-001 迷雾 + AUD-E-002 指纹 stamp）。
- **M 线**：用户问「帮我组个克制水系队」→ 顾问查库 → `validate_team` 硬闸 → `simulate_matchups` → 结构化建议（阵容/配招/性格/IV/理由/证据）；并具备 ScopeGate 越界拒答 + 回答评测集（保证建议合法、可追溯、不越界、可回归）。
- **R 线**：跑一段自博弈 → 沉淀记忆 + Playbook 编辑 → 胜率可测提升（R0 度量 → R1 记忆 → R2 信度 → R3 反思编辑）。

### 5.4 S1 — 集成验收（最小闭环 Gate）

- **E 线**：人机 + AI 对 AI 各打一局（真实 LLM 可选），轨迹落盘，`replay_record` 完美重放；改一个数据文件后旧轨迹 `data_digest` 隔离生效。
- **M 线**：离线顾问给出一条**通过 `validate_team`** 的组队建议（含性格/技能/IV/理由/证据），且越界/注入问题被 ScopeGate 正确拦截。
- **R 线**：`evolve step` 产出一次 Playbook 编辑并说明依据。
- **回归**：全量 `pytest` 绿；environment 不 import rock_pvp_agent；`git status` 干净。

## 6. 阶段 1 — 引擎保真度（完美复刻渐进，初步方案）

> 目标：把「简化但可跑的引擎」逐步逼近「完美复刻真实游戏环境」。**不阻塞、不重写**，只在冻结接口上增量加效果。

### 6.1 推进方式（每批一个 Gate）

- **技能效果批**：按 `mydocs/skill-batches/batch-P1..P6.json` 推进，P1∪P2 已实装，**P3 → P4 → … → P6** 逐个实装，直到 553 全实装。每批 = 实装 `SkillEffect` + 引擎结算 + 测试 + `valid_skills.json` 白名单扩展。
- **特性批**：按 `mydocs/trait-batches/batch-T-P1..P6.json` 推进，逐批实装特性效果（当前多为 default 白板）。
- **机制完善**：状态 / 天气 / 道具 / 萌化 / 首领化 / 进化链 / 冻结力竭等剩余机制（当前分支已开头的继续做完）。
- **引擎重构**：AUD-E-004 双循环归一（`BattleController` 复用 `drive_turn`）——放这里做，因为它是一次结构重构。

### 6.2 关键机制：数据指纹隔离让 M/R 自动跟踪

- 每批实装 → 数据文件变 → `data_digest` 变 → R 线记忆/Playbook 自动「跨版本隔离」、M 线轨迹证据自动「版本不匹配即排除」。
- **不需要**每次引擎改动后手工重做 M/R —— 签名冻结接口 + 指纹隔离已把它变成「数据升级后自动重基线」。
- 每批验收：新增效果有单测 + 既有确定性/迷雾/重放三不变式不回归 + 覆盖不降。

## 11. 一句话总结

**先在地基上把三线各自跑通并做齐（阶段 0 最小闭环：顾问含 ScopeGate/评测，只对标当前引擎），再把引擎逐批逼近真实（阶段 1），最后把进化与组队做到「真」的深度（阶段 2/3）。** 组队建议的「完善」与引擎保真度解耦——`data_digest` 指纹隔离 + 签名冻结接口让顾问和自博弈进化「边跑边随引擎升级自动重基线」，所以不需要等引擎复刻真实才开始把 chat mode 做完整。
