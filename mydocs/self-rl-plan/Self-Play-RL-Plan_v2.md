## 1. 执行摘要

v1 的问题在于：它说了「学习成果外化」，但没有说清**外化的搜索算法是什么**。v2 补上这一环，结论是三句话：

1. **搜索骨架用 GEPA 的候选池 + 实例级 Pareto 选择**。在自博弈场景下这个选择有一个 v1 没有意识到的性质：GEPA 的「实例」就是「对手」，于是**实例级 Pareto 前沿自动等价于元博弈的非支配策略集合**。同一个数据结构同时承担「反思式文本进化的父代池」和「PSRO 的策略种群」两个角色。这是 v2 的核心设计（§4）。
2. **变异算子用 SkillOpt 的有界编辑 + 严格门禁**。GEPA 原文的变异是对单个模块的自由重写；在自博弈的高噪声信号下这会擦掉好规则。改用有界 `L_t` 条 add/delete/replace、受保护慢更新区、被拒绝编辑缓冲区（§8）。
3. **部署期用 MemRL 的情节记忆 + AMC 的后验采样**。前者让同类局面复用历史效用（`Q`），后者在关键回合把冻结先验往「赢」的方向偏移。两者都不动权重，但**都需要一个价值估计器**，这是 v2 唯一引入梯度的地方，且梯度只作用在外挂小模型上（§2、§10、§11）。

四篇论文的机制映射：

| 论文 | 核心机制 | 在本项目承担的角色 | 关键适配改动 |
|---|---|---|---|
| **GEPA** | 反思式提示进化；实例级 Pareto 候选选择；evaluation traces + 反馈函数 `μ_f`；system-aware Merge；模块轮询 | Playbook 的**搜索算法**；候选池即自博弈种群 | 「实例」重定义为「对手 × 阵容族」；反馈函数由确定性引擎生成（§7） |
| **SkillOpt** | 有界编辑 `L_t`；留出集严格改进门禁（平手拒绝）；被拒绝编辑缓冲区；epoch 慢更新写入受保护区；只给优化器的 meta-skill | Playbook 的**编辑纪律与晋级门**；防止自博弈噪声下的文本漂移 | 门禁的「分数」换成配对胜率 + 可利用性的复合分（§8.5） |
| **MemRL** | Memory-Based MDP；`(意图 z, 经验 e, 效用 Q)` 三元组；两阶段检索（相似度门 → `(1−λ)·sim + λ·Q` 重排）；`Q ← Q + α(r − Q)`；成功与失败双记忆；只增不删 | **部署期**的局面级经验召回；跨对局迁移具体打法 | 用反事实回放替代 MemRL 的 uniform reward broadcast，修掉其公开承认的信度分配弱点（§9.4） |
| **AMC** | KL 正则 RL ≡ 贝叶斯推断，`π*(s_{0:T}) ∝ π(s_{0:T})·e^{r/β}`；序列重要性重采样；学习到的软价值函数 `V_θ`；固定步重采样；`N=15` | **关键回合的推理期增强**；同时提供 §8 的关键回合定位信号 | 强先验饱和会反转收益，必须由不确定性门控（§11.4） |

**与 v1 的差异清单**：v1 的「反思 → 合并 → 截断 → 门禁」单链改为「候选池 + Pareto 父代选择 + 有界变异 + 两级门禁」；v1 未定义的反馈函数补齐为规格；v1 的五层记忆补上可计算的检索与效用更新规则；v1 的 SMC 从「可选」升级为关键回合的默认路径并给出门控条件；v1 的「Numerics」明确拆成「零梯度档」与「小模型档」。

## 2. 「无参数更新」的严格定义

这一节先立边界，因为四篇论文对「不更新权重」的严格程度并不相同，混着抄会得到一个自相矛盾的方案。

**本方案的承诺**：

| 对象 | 是否允许训练 | 说明 |
|---|---|---|
| 闭源前沿模型（Fable 5 等） | **绝对不动** | 不做 SFT / RLHF / GRPO / DPO / LoRA / 任何梯度。只通过上下文影响它 |
| Playbook（多模块文本） | 训练（文本空间） | GEPA + SkillOpt 的搜索对象 |
| Situation Memory（情节记忆库） | 训练（表项与 `Q` 值） | MemRL 的更新规则，纯算术，无梯度 |
| Build Book / 收益矩阵 / `σ*` | 训练（枚举与线性代数） | PSRO 元求解，无梯度 |
| 阈值表（一击必杀线等） | 训练（穷举） | 规则引擎计算，无梯度 |
| `V_θ` 价值估计器 | **两档，见下** | 这是全方案唯一可能出现梯度的位置 |

**`V_θ` 的两档实现**（重要决策，S3 之前必须选定）：

- **档位 A（零梯度，推荐起步）**：手工特征 + 梯度提升树 / 逻辑回归。特征是本游戏可穷举的：命数差、双方场上血量比、能量差、当前克制关系得分、对手已暴露技能数、后台可换人数、回合序数。这不是深度学习，训练一次几秒，可完全版本化，可解释。本游戏的状态维度低到手工特征够用，先假定档位 A 成立。
- **档位 B（外挂小模型，AMC 原方案）**：3B–11B 小模型 + LoRA + 回归头，按 AMC 式 `V_θ(s_t) = f_θ(s_t) + r(s_t)`，用单轨迹回归损失训练。只在档位 A 的中局胜率预测 AUC 长期低于 0.75 时启用。

必须承认的一点：AMC 的消融显示**纯 prompting 的 SMC（不训练价值函数）表现不稳定**——「让大模型自己估胜率」代替 `V_θ` 是不可行的替代方案。所以「完全零学习器」不是一个选项；档位 A 是零梯度但仍然是学习器。这是本方案对「无参数更新」这个词唯一的、显式的让步：**被优化的那个模型不更新，外挂的廉价估计器可以更新**。

**部署期成本承诺**（对齐 SkillOpt 的 zero inference-time overhead）：常规回合的额外开销只有注入的文本（Playbook ≤ 2,500 token + 检索到的 ≤ 3 条记忆）。优化器模型只在离线循环里出现，永不进入线上路径。关键回合的 SMC 是显式的成本换胜率决策，由 §11.4 的门控管理。

## 3. 可训练状态的四层结构

四层，按更新频率从慢到快排列。分层的理由和 v1 §4.1 相同（信号时间尺度差 2–3 个数量级），但 v2 把每层的载体、算法、评判都钉死了。

| 层 | 载体 | 更新频率 | 算法 | 评判者 |
|---|---|---|---|---|
| **L-Build** 构筑 | Build Book（阵容池 + `σ*`） | 每个 PSRO 轮 | 双 Oracle + 元求解 | 联赛收益矩阵 |
| **L-Play** 战术文本 | Playbook（多模块） | 每个优化 step | GEPA 搜索 + SkillOpt 编辑 | `D_sel` 配对胜率 |
| **L-Mem** 情节记忆 | Situation Memory | 每场对局 | MemRL 式 `Q` 更新 + 追加 | 反事实回放派生的信度 |
| **L-Post** 后验偏移 | 无持久载体（推理期行为） | 每个关键回合 | AMC 式 SIR | `V_θ` |

### 3.1 Playbook 拆成多模块（GEPA 化的关键前提）

v1 把 Playbook 当作一整块文本。这是错的：GEPA 的搜索是**按模块轮询**优化的，一整块文本意味着每次变异的搜索维度过高、信号归因不清。v2 把它拆成 5 个独立可优化模块，每个模块对应决策管线里的一个 LLM 调用点：

```
M1  team_reader      对手建模：从公开事件推断对手配置倾向与后台威胁
M2  action_selector  技能/换人选择（主决策模块）
M3  energy_planner   能量收支规划：何时回能、何时透支
M4  endgame          残局（任一方剩 1 命）
M5  build_proposer   构筑提议（只在 L-Build 阶段激活，对战期不调用）
```

每个模块是一份独立的自然语言指令块，各带自己的 `[PROTECTED]` 慢更新区。硬上限：单模块 800 token，M1–M4 合计 ≤ 2,500 token。SkillOpt 的实测支撑这个预算——它的六个基准最终技能是 379–1,995 token（中位约 920），且**全部收益来自 1–4 次被接受的编辑**。所以设计目标不是「写一份长手册」，而是「找到那 1–4 条真正有效的规则」。

模块化还带来一个副产品：GEPA 的 system-aware Merge 变得可用。两个候选如果分别在 M1 和 M3 上取得了改进，可以模块级交叉合并出一个继承双方优点的新候选（§8.6）。

### 3.2 Build Book

沿用 v1 §3.2 的 YAML 结构（`archetype` / `counters` / `countered_by` / `meta_share`），字段语义不变。所有 L2 提议必须先通过 `schemas/v1/creature-build.schema.json` 校验，再加上三条内容包约束：努力值三维各 +21~30、血脉从 18 系中选一、技能必须在该 form 的 `skill_pool` 内且 `kind: bloodline` 的技能至多装一个。

### 3.3 Situation Memory

见 §9。

### 3.4 Numerics

`V_θ`（§2 两档）、抽象局面混合频率表、伤害阈值表、经验收益矩阵、`σ*`。全部零梯度（档位 A 下）。

## 4. 核心设计：Pareto 候选池 ≡ 自博弈种群

这是 v2 最重要的一节，也是把「提示优化」和「种群自博弈」缝合起来的地方。

### 4.1 GEPA 的候选选择做了什么

GEPA 维护一个候选池，每个候选在 `D_pareto` 上有一个**逐实例分数向量**。选父代时（原文 Algorithm 2）：

1. 对每个实例 `i`，求所有候选在该实例上的最好分 `s*_i`；
2. 在实例 `i` 上达到 `s*_i` 的候选，记为该实例的「优胜者」；
3. 汇总所有实例的优胜者集合，剔除被支配的候选，得到 Pareto 前沿；
4. **按各候选领先的实例数为权重**采样一个父代。

GEPA 的消融（原文 Table 3）显示这个策略明显优于「只选最优候选」——因为后者在局部最优里打转。

### 4.2 在自博弈里，「实例」就是「对手」

把 `D_pareto` 的实例定义为 `(对手策略 o, 阵容族 f, 种子集)` 三元组，那么候选的分数向量就是**对各对手的胜率向量**。此时：

- 「候选 A 支配候选 B」= A 对每一个对手的胜率都不低于 B → 正是元博弈中的策略支配关系。
- 「Pareto 前沿」= 不被任何单一策略全面压制的策略集合 → 正是 PSRO 需要维护的种群，也正是非传递性游戏里必须保留的多样性。
- 「按领先实例数加权采样父代」= 按「能打赢多少种对手」加权 → 天然近似元博弈的支撑集权重。

**结论**：v1 里分立的两个东西（Playbook 优化的候选历史、PSRO 的策略种群）合并成一个数据结构。这带来三个实际好处：

1. **防策略循环是免费的**。v1 需要额外的 PFSP 机制来防止「打赢上一代但打不过三代前」；在 Pareto 池里，三代前的候选只要还在某个对手上领先就不会被淘汰，它自动留在池中并继续被采样为父代和对手。
2. **对手分布不用手调**。v1 §7.1 手工规定了 40/20/20/10/10 的对手池配比；v2 直接从 Pareto 前沿按领先实例数采样对手，配比由数据决定。手工配比降级为兜底（当前沿退化到 1–2 个成员时启用）。
3. **非传递性从缺陷变成资产**。收益矩阵反对称分量高 → Pareto 前沿宽 → 父代多样性高 → 搜索不易早熟。所以 v1 §6.3 的「反对称分量占比」指标在 v2 里同时是健康度指标：它掉到接近 0 反而说明池坍缩了。

### 4.3 池的规模与剪枝

Pareto 前沿会随时间变宽，全量评测成本是 `|池| × |实例|`。GEPA 原文承认「大部分 rollout 预算花在验证上」。控制手段：

- 前沿上限 `P_max = 12`。超出时剔除「领先实例数最少且与另一成员胜率相关性 > 0.9」的成员（冗余而非弱）。
- 被剔除的成员移入**历史池**（archive），不再作为父代，但仍作为回归门禁的对手（§12）。永不物理删除。
- 新候选先在 minibatch（3–8 场）上过廉价门，只有改进的才付全量 `D_pareto` 评测（GEPA 原文同一逻辑）。

## 5. 数据划分

三集隔离，SkillOpt 与 GEPA 一致，但按**阵容族与场景族**切分而不是按对局切分（否则同阵容对局跨集泄漏）。

| 划分 | 别名 | 内容 | 用途 | 禁止 |
|---|---|---|---|---|
| `D_tr` | = GEPA 的 `D_feedback` | 自博弈对局池 | 产生 rollout 与反思证据；反馈文本可被优化器读取 | — |
| `D_sel` | = GEPA 的 `D_pareto` | 固定 60 个阵容族 × 场景组合，每个配 8 个固定种子的配对对局 | 计算逐实例分数向量、Pareto 前沿、门禁判定 | 实例内容不进反思上下文（只有分数可见） |
| `D_test` | 隐藏集 | 人工反套路场景 + 未公开阵容 | 只用于汇报 | 不进任何优化输入；CI 不可读；每季度换血 30% |

`D_sel` 的实例定义即 §4.2 的 `(对手, 阵容族, 种子集)`。规模建议 60 个实例起步——GEPA 明确指出验证集是主要成本项，可以缩小或动态子采样。

## 6. 反馈函数 μ_f（本方案最重要的工程投入）

GEPA 全文反复强调：它的收益来自**评估痕迹（evaluation traces）而非仅最终分数**，而把系统内部的可诊断信息暴露成自然语言，是需要人工设计的。本项目的优势是规则引擎完全自研，可诊断信息极其丰富——不用就浪费了。

`μ_f(轨迹) → (feedback_text, score)`。**`feedback_text` 完全由确定性引擎生成，绝不由 LLM 撰写或评分。**

回合级 `feedback_text` 模板（从 `TurnSettlement` 事件流渲染）：

```
[T23] 我方行动: use_skill(attack_x, cost=3)  能量 5→2
      对手行动: use_skill(defend_y)          [同时行动，本回合我方被读中]
      结算: 伤害 12 → 被防御技能减免至 4；对手血量 61→57 (-6.5%)
      克制关系: attack vs defend = 0.55 不利（非完全克制，期望倍率 0.7）
      模型自报预测: "预计造成 30+ 伤害并逼换" → 实际 4，偏差 -87%  ★校准失败
      能量后效: 我方能量 2，下回合无法使用 attack_x(3)，被迫回能或换人
      可选替代动作: switch(creature_4) / use_skill(status_z, cost=2) / use_skill(recover_energy)
[T24] ... 我方被迫 use_skill(recover_energy)，对手 use_skill(attack_p) 造成 22 伤害
      → 事后归因: T23 的能量透支导致 T24 的免费挨打回合
[终局] 败（我方 0 命 / 对手 2 命，共 41 回合）
```

设计要点：

- **暴露机制而非结论**。写「克制倍率 0.7」而不是「这步不好」。结论由优化器模型自己推，这样它才能推出可泛化的规则。
- **暴露反事实的存在**。列出当时的合法替代动作，让反思有可比对象。
- **暴露预测校准偏差**。`DecisionResponse.prediction` 与实际结算的偏差是**认知错误**的直接证据，比胜负信号干净得多——它区分了「运气差」和「算错了」。这是本项目相对 GEPA 原文基准的额外信息源。
- **暴露跨回合后效**。能量是本游戏的真实资源，透支的代价往往在 1–2 回合后兑现，`feedback_text` 必须把这个链条显式写出来，否则反思器无法定位。

`score` 部分：终局胜负是唯一奖励锚（沿用 v1 §8，`r ∈ {+1, −1}`）。密集代理量（Δ命数差、Δ血量差、Δ能量差）**只进 `feedback_text` 与 `V_θ` 训练，绝不进 `score`**。理由不变：自博弈里 shaping 偏置会被双方共同放大。

## 7. 信度分配

稀疏奖励下，「这一局输了」要归到具体回合。三个信号，按成本递增，取交集优先：

1. **价值落差**（便宜，覆盖广）：用 `V_θ` 扫全场，取 `V(s_t) − V(s_{t+1})` 下降最大的 top-k 回合。
2. **校准偏差**（免费，精度高）：`feedback_text` 中标记 ★ 的回合。这是零额外成本的信号，应当优先消费。
3. **反事实回放**（贵，产生真标签）：固定其余全部输入与种子，把候选回合的动作替换为另一合法动作，重跑 `M=24` 次。若替代动作胜率显著更高，则确认为错误决策，**并同时得到一个更优动作标签**。

反事实回放的产出是 v2 相对 MemRL 的关键改进（§9.4）：它给出**逐回合**的效用增量，而 MemRL 只能把终局奖励均匀广播给所有被检索的记忆条目。

关键回合卡片（送入反思器与记忆库的统一结构）：

```json
{
  "trajectory_id": "...", "turn_no": 23,
  "situation_key": {
    "my_lives": 2, "opp_lives": 3, "my_energy_band": "low",
    "field_matchup": "fast_attacker_vs_wall", "opp_revealed_skills": 3,
    "phase": "mid"
  },
  "chosen": "use_skill:attack_x",
  "counterfactual_better": "switch:creature_4",
  "delta_winrate": 0.19, "n_replays": 24,
  "signals": ["value_drop", "calibration_miss", "counterfactual_confirmed"],
  "feedback_text": "...(§6 渲染结果)...",
  "module_attribution": "M3 energy_planner"
}
```

`module_attribution` 是 GEPA 模块轮询需要的：这次失误该归到哪个模块，决定它会成为哪个模块的变异证据。

## 8. 内层优化循环（GEPA 骨架 + SkillOpt 算子）

一个 step 的完整流程。这是 v2 的主算法。

```
输入: 候选池 P（每候选 = 5 个模块文本 + 在 D_sel 上的分数向量）
      被拒绝编辑缓冲区 R（epoch 局部）
      Meta Playbook（只给优化器）

① 父代选择      c ← ParetoSelect(P)                      # GEPA Alg.2，§4.1
② 模块选择      m ← RoundRobin(M1..M4)                   # GEPA 的模块轮询
③ 对手采样      o ← 从 Pareto 前沿按领先实例数加权采样    # §4.2 替代 v1 的 PFSP
④ Rollout       用 c 对 o 跑 B=8 场配对对局（双向先后手、固定种子）
                → 轨迹 + μ_f 反馈文本（§6）
⑤ 信度分配      → 关键回合卡片（§7），按 module_attribution 过滤出属于 m 的
⑥ 双分析师反思  Failure Analyst（失败卡片 + R）
                Success Analyst（成功卡片）
                → 结构化 add/delete/replace 编辑提案
⑦ 分层合并      失败侧内部合并 → 成功侧内部合并 → 合并两侧（失败优先）
                去重、消解矛盾、剔除实例特异的建议
⑧ 有界截断      按 (证据条数 × 平均 delta_winrate × 场景覆盖度) 排序，截到 L_t 条
                不得覆写 [PROTECTED] 区
⑨ 廉价门        候选 c' 在同一 minibatch 上重跑；未改进 → 写入 R，本 step 结束
⑩ 全量门        c' 在 D_sel 上评测 → 分数向量
                加入 P 的条件：向量在至少一个实例上取得池内最优（即进入 Pareto 前沿）
                成为 Champion 的条件：复合分严格超过当前 Champion（平手拒绝）
```

### 8.1 为什么是两级门禁

GEPA 的接受条件宽松（minibatch 改进即入池），因为它靠池的多样性兜底；SkillOpt 的接受条件严格（`D_sel` 严格超过，平手拒绝），因为它只有一条链。两者都对，但目标不同。v2 分工：

- **入池门（宽）**：只要在某个对手上做到池内最优就入池。保多样性，对抗非传递性。
- **晋级门（严）**：成为线上 Champion 必须在复合分上严格超过。防漂移。SkillOpt 明确指出严格不等号让「被拒绝的编辑成为有信息的负反馈，而不是隐藏状态」。

Champion 复合分（沿用 v1 §5.2 的权重，分子改为 Pareto 池加权）：

```
score = 0.70 · 对 Pareto 前沿按 meta_share 加权的配对胜率
      + 0.15 · (1 − 可利用性)              # 专职剥削者攻击后的胜率保持
      + 0.10 · 预测校准 (1 − Brier)
      + 0.05 · 合法率与降级率健康度
```

### 8.2 有界编辑预算 L_t

SkillOpt 的消融给出的实测结论值得直接照抄：`L_t ∈ {1,2,4,8,16}` 的扫描里**任何适度有界预算都优于无预算重写**（无 lr 组在三个基准上分别低 1.9 / 4.5 / 4.8 分），而具体调度器（constant / cosine / linear）之间差异不大。所以：

- 默认 `L_t = 4`，余弦退火到 1。
- 不要在调度器选择上花时间——**有界本身**才是收益来源。
- 反思 minibatch `B_m = 8`；rollout batch `B = 8`。SkillOpt 显示这两个维度都很平（`B_m` 从 1 到 32、`B` 从 8 到全 epoch，分数波动都在几分内），不必调参。
- 但**证据总量确实要够**：SkillOpt 的 panel (a) 显示训练集用量从 1% 到 100%，程序性基准从 47.5 涨到 78.0。对本项目意味着：不要在几十场对局上就下结论。

### 8.3 被拒绝编辑缓冲区

epoch 局部，记录每个被拒编辑的内容 + 它造成的分数下降 + 对应的失败模式。后续同 epoch 的反思调用都能读到它。SkillOpt 消融：移除它在三个基准上掉 1.6 / 4.6 / 2.4 分。零部署成本，必做。

### 8.4 Epoch 慢更新与 Meta Playbook

每 `E = 8` step 一次：

1. 用**上一 epoch 的 Champion**和**当前 Champion**在同一批 20 个训练实例上各跑一遍，分成四类：改进 / 回退 / 持续失败 / 稳定成功。
2. 优化器把纵向结论写进各模块的 `[PROTECTED]` 区（markup 围栏，step 级编辑无法覆写）。**这个慢更新候选同样要过门禁**——SkillOpt 强调它不是免检通道。
3. 更新 **Meta Playbook**（只给优化器，永不上线）：哪类编辑常被拒、哪类诊断方向反复奏效、哪些失败跨 epoch 持续存在。
4. 重训 `V_θ`；在 `D_test` 上跑一次汇报评测（不用于任何决策）。

SkillOpt 消融里这一项的权重最重：**同时移除 meta-skill 和慢更新，程序性基准从 77.5 掉到 55.0（−22.5 分），是全部消融中最大的退化。** 本游戏是高度程序性的（能量收支、换人时机、克制读法都是流程知识），所以这一项必须实现，不能当作 nice-to-have。

### 8.5 每个 step 记录 `edit_apply_report.json`

逐条编辑的接受/跳过状态与原因，保证 Champion 的每一处文本变化都可事后追溯到证据。审计性是文本空间学习相对权重更新的核心优势，别丢掉。

### 8.6 Merge（可选，epoch 边界）

GEPA 的 system-aware Merge：找两个**血缘互补**的候选（分别改进了不同模块），做模块级交叉。本项目天然适配，因为 §3.1 已经把 Playbook 拆成 5 个模块。约束（GEPA 原文的配置）：每个 epoch 至多 5 次 merge 调用，合并结果同样走两级门禁。

注意 GEPA 自己的结果里 Merge 并非稳定为正（IFBench 上 GEPA+Merge 反而低于 GEPA）。所以 Merge 列为可选项，S6 之后再启用，且必须能一键关闭。

## 9. Situation Memory（MemRL 化的部署期记忆）

Playbook 学的是**可泛化的流程规则**；但有些知识是**局面特异**的——「面对这个特定阵容的这个特定开局，先换人再回能」。这类知识写进 Playbook 会污染它的泛化性（SkillOpt 明确要求学到的技能是 procedural 而非 instance-specific）。它应该进一个可检索的记忆库。

### 9.1 记忆条目

MemRL 的三元组 `(意图 z, 经验 e, 效用 Q)`，在本项目具体化为：

```json
{
  "entry_id": "...",
  "z": {                                  // 意图/局面键：检索用
    "text": "能量偏低、我方剩2命、场上被高速攻击型压制、对手后台疑有状态型",
    "embedding": [...],
    "struct": { /* §7 的 situation_key，用于硬过滤 */ }
  },
  "e": {                                  // 经验：注入用
    "kind": "success | failure",
    "action": "switch:pivot_role_creature",
    "rationale": "换人吸一回合伤害同时自然回能，比原地回能少挨一次高倍率攻击",
    "mechanism": "换人不消耗能量；回能技能在被高速攻击型压制时等于送一个免费回合"
  },
  "Q": 0.41,                              // 效用
  "n_used": 17,
  "provenance": { "content_pack_digest": "...", "rules_engine_version": "..." }
}
```

**成功与失败都要存**。MemRL 的失败条目走「反思」模板（记录该避免什么及为什么），成功条目走「脚本」模板（记录可复现的动作序列）。本项目照抄这个二分，因为失败记忆在同时行动博弈里尤其值钱——它记录的是「这样出会被读穿」。

### 9.2 两阶段检索

第一阶段，相似度门：只保留 `sim(z_query, z_i) ≥ δ` 的条目，取 top-`k1`。加一道本项目特有的硬过滤——`struct` 字段中的命数阶段与能量档必须匹配，`content_pack_digest` 必须兼容。跨版本的记忆不可信，必须隔离。

第二阶段，效用重排：对 `k1` 个候选，把 `sim` 和 `Q` 各自做 z-score 标准化后合成

```
rank_score = (1 − λ) · z(sim) + λ · z(Q)
```

取 top-`k2` 注入决策上下文。默认 `λ = 0.5`、`k1 = 20`、`k2 = 3`、`δ` 按嵌入模型标定（取使召回率约 0.8 的分位点）。两阶段的必要性：只按相似度会召回「很像但当时打输了」的经验；只按效用会召回「很好但场景不符」的经验。

### 9.3 效用更新

```
Q ← Q + α (r − Q)      α = 0.3
```

新条目 `Q_init = 0`。只增不删——MemRL 不做淘汰或衰减，并用 **Forgetting Rate** 指标监控库的稳定性。本项目沿用，但增加一条：`content_pack_digest` 不兼容的条目标记为 `retired`，从检索候选中排除而不删除（保留用于跨版本回归分析）。

### 9.4 修掉 MemRL 的信度分配弱点

MemRL 论文自己承认的局限：终局奖励 `r` 被**均匀广播**给本次检索到的所有条目，因此一条无关的记忆可能因为搭上一场胜利而涨 `Q`。在自博弈里这个偏差会被放大——对局数量巨大，噪声会把 `Q` 洗成随机排序。

v2 的修法，利用本项目独有的确定性引擎：

```
r_entry = w_used · r_terminal + (1 − w_used) · delta_winrate(该条目实际被采纳的那个回合)
其中 delta_winrate 来自 §7 的反事实回放；
若该条目被检索但其建议动作未被采纳 → 不更新（无归因依据）；
若被检索且采纳但无反事实回放数据 → 只用 r_terminal，且用半衰的 α' = α/2 更新（降低噪声条目的话语权）。
w_used = 0.3
```

这把 MemRL 的「广播」换成「按实际采纳与实际因果贡献归因」。这是本方案里唯一一处对参考论文的实质性算法修正，代价是需要反事实回放（贵），所以只对**关键回合被采纳的记忆**做精确归因，其余走半衰路径。

### 9.5 记忆 vs Playbook 的边界

一条经验反复在多个阵容族上以高 `Q` 被采纳（建议阈值：跨 ≥ 3 个阵容族、`n_used ≥ 10`、`Q ≥ 0.3`）→ 提名为 Playbook 的编辑候选，进入 §8 的门禁流程。这是「情节记忆 → 语义规则」的固化通道，对应 RockPvP_PLAN v1 §7 五层记忆的层间流动。

反向不成立：Playbook 的规则不下沉为记忆条目。避免同一知识两处存放导致上下文冗余。

## 10. 关键回合的后验采样（AMC 化）

### 10.1 为什么这在本项目成立

AMC 的核心恒等式：KL 正则化 RL 的最优策略是先验的重加权后验

```
π*(s_{0:T}) ∝ π(s_{0:T}) · exp(r / β)
```

先验 `π` 就是冻结的闭源模型。既然不能优化先验的参数，就**从后验采样**。实现方式是序列重要性重采样：并行维护 `N` 条候选轨迹，在固定检查点按重要性权重剪掉差的、复制好的。

AMC 的权重更新（原文 Eq.4）：

```
w_t = w_{t−1} · exp( V(s_t) − V(s_{t−1}) + r(s_{t−1}) / β )
```

其中 `V` 是软价值函数，AMC 用 `V_θ(s_t) = f_θ(s_t) + r(s_t)` 的形式训练（原文 Eq.6/7，单轨迹回归目标即可）。

本项目的适配：

- `N = 15`（AMC 默认）。候选是「本回合动作 + 后续 2–3 回合的展开」而非整局——本游戏一局 40–60 回合，整局 SMC 成本不可接受。
- **固定重采样点**，不用 ESS 动态触发。AMC 明确报告稀疏定点重采样在分数和成本上都更优。本项目的固定点：换人决策点、能量归零点、任一方剩 1 命时、对手首次暴露新技能后的下一回合。
- `β` 从 `D_sel` 上标定，不手拍。

### 10.2 必须诚实说明的适用边界

AMC 自己的结果里有一个反转：**GPT-5.1 在 TextCraft 上，Best-of-15 得 0.889，AMC 只有 0.790。** 强先验在简单任务上已经接近饱和，此时 SMC 的重加权反而是伤害。

这不是边缘案例，而是对本项目的直接警告——Fable 5 级别的模型在**简单局面**（比如「对手剩 1 命且我方能一击必杀」）上本来就不会犯错，在这种回合做 SMC 是纯浪费甚至有害。

因此 SMC 必须**门控**：

```
启用条件（全部满足）：
  1. 当前回合命中 §10.1 的固定重采样点之一
  2. V_θ 的不确定性高（Top-2 候选动作的价值差 < τ，τ 从 D_sel 标定）
  3. 本场对局的 SMC 预算未耗尽（每场上限 4 次）
否则：走单次调用（Playbook + 检索记忆，无额外采样）
```

并且必须在 `D_sel` 上持续验证「SMC 分支的胜率 > 同成本 Best-of-N 的胜率」。这个不等式一旦反转就关闭 SMC——它是成本换胜率的交易，不是免费午餐。

### 10.3 与 GEPA 层的关系

两者互补且**不能互相替代**：

- Playbook（GEPA/SkillOpt 层）改变的是**先验的条件分布**——把模型引导到更好的动作分布上，零推理开销，永久生效。
- SMC（AMC 层）改变的是**从给定先验中采样的方式**——不改变先验，只在关键点做搜索，有推理开销，逐回合生效。

先做 Playbook（S2–S3），后做 SMC（S7）。原因：SMC 的收益依赖先验「好但不完美」，Playbook 变好会让先验更好，从而**缩小** SMC 的收益空间。反过来先上 SMC 会让 Playbook 的评测信号被采样噪声污染。顺序不能颠倒。

## 11. 外层：构筑元游戏

沿用 v1 §6 的三级分解与双 Oracle 循环，此处只记 v2 的三处修改。

### 11.1 三级分解（不变）

| 级别 | 空间 | 谁来搜 |
|---|---|---|
| L1 战术原型 | ~20 个原型（能量压制 / 高速强攻 / 耐久消耗 / 状态控制 …） | LLM 提议（模块 M5） |
| L2 精灵与技能选择 | 给定原型下 6 只 × 各 4 技能 | LLM 提议 + schema 与内容包约束校验 |
| L3 数值分配 | 努力值（三维各 +21~30）、性格、血脉系别 | **纯代码搜索**（局部搜索 + 阈值表剪枝） |

L3 交给代码的理由不变：最优努力值通常由「能否跨过某个一击必杀阈值」决定，这是可枚举的，而 LLM 手算必错。

### 11.2 修改一：Build Oracle 的提议器就是 Playbook 的 M5 模块

v1 把 Build Oracle 当作独立组件。v2 把它变成 Playbook 的第 5 个模块，于是**构筑提议能力本身也是被 GEPA 优化的对象**：它的反馈是「提议的阵容在联赛中对 `σ*` 的胜率」，它的编辑走同一套有界编辑 + 门禁。这消掉了 v1 里一个未定义的环节（「LLM 怎么变得更会选队」）。

### 11.3 修改二：收益矩阵与 Pareto 分数向量共用一套评测

§4.2 已经让 `D_sel` 的实例带上阵容族维度，所以联赛的成对结果直接就是收益矩阵的条目。不需要跑两套评测。

### 11.4 修改三：元求解结果 `σ*` 反过来给 Pareto 采样加权

§8 的 ③ 对手采样用「领先实例数」加权。当收益矩阵已经解出 `σ*` 后，改用 `σ*` 的支撑集权重——更准确，因为它考虑了对手之间的相互关系而非只数领先次数。两者在早期（矩阵稀疏时）用前者，成熟后用后者。

### 11.5 非传递性的显式度量（不变）

每轮联赛后计算收益矩阵的反对称分量占比；维护克制图谱（有向图，边权 = 配对胜率 − 0.5）并检测三元环；汇报时同时给出 Elo 与 α-rank，冲突时以 α-rank 为准。区别是 v2 里这个指标同时是**池健康度**指标（§4.2）。

## 12. 防坍缩

v2 的防坍缩大部分由 Pareto 池结构免费提供（§4.2），剩下三件事仍需专门做。

| 失败模式 | v1 的防御 | v2 的防御 |
|---|---|---|
| 策略循环（打赢上一代却打不过三代前） | 手工 PFSP 配比 | **Pareto 前沿自动保留**；手工 PFSP 降级为前沿退化时的兜底 |
| 过拟合自身（只会打镜像） | 专职剥削者 + 风格对手池 | 保留：**专职剥削者仍是唯一的可利用性度量**，Pareto 池无法替代它 |
| 评测污染（分涨真实强度不涨） | 三集隔离 + 隐藏基准 | 保留，并加 GEPA 的纪律：优化器**只能看到 `D_sel` 的分数，看不到 `D_sel` 的实例内容** |

### 12.1 专职剥削者

单独的候选分支，唯一目标是打爆当前 Champion。不进主线、不参与晋级，只做两件事：(1) 它的胜率就是 Champion 的**可利用性**，直接进 §8.1 复合分的 0.15 项；(2) 它的对局注入主线对手池。每 2 个 epoch 从 Champion fork 重置一次，避免它自己过拟合。

为什么 Pareto 池替代不了它：池里的成员都是「为了赢整体」而进化的，没有一个是「专门针对 Champion 的弱点」而进化的。可利用性必须由定向攻击来测。

### 12.2 健康度看板（异常即暂停自博弈）

- **动作熵**：同时行动博弈中过低的熵会被读穿。设下界告警。
- **换人率**：塌到 0 或飙到极高都是退化。
- **能量利用率**：回能技能使用频率是否落在合理区间。
- **对局长度分布**：突然变短通常是双方都在乱打。
- **Pareto 前沿宽度 + 收益矩阵反对称分量**：坍缩到 1–2 个成员即报警。
- **Forgetting Rate**（MemRL 指标）：记忆库中曾被成功采纳、后续同类局面却不再被召回的比例。
- **编辑接受率**：长期为 0 说明搜索卡死；长期过高说明门禁太松或 `D_sel` 太小。

### 12.3 历史回归门禁

Champion 晋级前必须对**历史池**（§4.3 被剔除的成员 + 历次 Champion）全部跑一遍，对任一历史成员胜率不得低于 45%。这是「真实变强」而非「循环」的硬检验。

## 13. 评测与晋级

### 13.1 评测矩阵

| 维度 | 内容 |
|---|---|
| 对手 | 当前 Champion、Pareto 前沿全体、3 个历史 Champion、专职剥削者、启发式 Bot、3 种极端风格 |
| 阵容 | ≥ 5 个战术原型，双方各自采样 |
| 种子 | ≥ 20 个固定种子，先后手全交换（配对对局） |
| 场景 | 100 个人工关键局面（能量枯竭 / 残局 / 被状态压制） |
| 故障注入 | 模型超时、坏 JSON、非法动作、工具失败四类 |
| 版本 | 当前 `content_pack_digest` + 一个历史版本 |

### 13.2 晋级门禁

```
必要条件（全部满足）：
  1. 规则与协议测试 100% 通过；非法动作率 ≤ 当前 Champion
  2. 复合分（§8.1）严格超过当前 Champion —— 平手拒绝
  3. 对 σ* 的配对胜率提升达到统计显著（配对 bootstrap 或 SPRT）
  4. 可利用性（剥削者攻破率）不显著上升
  5. 历史池无严重回归（对任一历史成员胜率 ≥ 45%）
  6. 预测校准不显著恶化（Brier score）
  7. 动作熵不低于健康区间下界
  8. 延迟与成本在预算内，或胜率增益达到预设交换比
晋级路径：Challenger → 影子运行 → 小流量灰度 → Champion
注册表保留一键回滚；每次晋级归档 5 模块文本 + edit_apply_report + 分数向量。
```

用 SPRT（序贯概率比检验）而非固定场次：强候选早停晋级、弱候选早停拒绝。

### 13.3 汇报纪律

任何「提升了 X%」必须附带：样本量、种子范围、置信区间、对手构成、`content_pack_digest`、Playbook 版本、`V_θ` 版本。缺一不可信。`D_test` 只在 epoch 边界跑，且结果不得回流到任何优化决策。

## 14. 成本模型

四篇论文都强调成本，且给了可对照的数量级。

**GEPA 的教训**：它的大部分 rollout 预算花在**验证**（候选选择）上，而非产生学习信号。它只用 79–737 次训练 rollout 就达到最优，却要花几千次验证 rollout。对本项目的直接推论：**`D_sel` 的规模是主要成本旋钮**，不是 rollout batch 大小。控制手段是缩小 `D_sel` 或动态子采样实例（GEPA 原文明确把这列为未来方向，我们可以直接实现）。

**SkillOpt 的教训**：全部收益来自 1–4 次被接受的编辑，最终文本 379–1,995 token。所以不要期待也不要允许大规模重写。

**AMC 的教训**：SMC 比同等强度的 Best-of-15 便宜 ≥ 50%，但只在先验不饱和时。

本项目的控制手段（按性价比排序）：

1. **对手用便宜档位**：只有被优化的一方用前沿模型，对手方用快模型或启发式 Bot。
2. **提示缓存**：Playbook + 图鉴静态部分是每回合重复的大前缀，必须缓存。这是本项目最大的单项省钱手段。
3. **分级决策**：`V_θ` 高置信回合走单次调用甚至纯启发式；只在关键回合花预算。
4. **两级门禁的廉价门**（§8 步骤⑨）：绝大多数候选死在 8 场 minibatch 上，不付全量 `D_sel` 代价。
5. **反事实回放共享前缀**：同一局面的 24 次回放共享上下文前缀。
6. **SPRT 早停**。
7. **优化器模型可与目标模型同档**：SkillOpt 的实测显示 target-matched optimizer 仍能回收强优化器 56–74% 的收益。预算紧时这是可接受的降级，不是失效。

按 step 记账，单 step 成本 = `B` 场 rollout + 关键回合挖掘（含回放）+ 反思调用 + 门禁评测。

### 15.2 分阶段计划

| 阶段 | 目标 | 交付 | 退出标准 |
|---|---|---|---|
| **S0** 环境就绪 | 图鉴可用 + 引擎可对战 | 填充 content pack（当前 `creatures.json` 等**仍为空**，`effort_rules.json`/`bloodline_rules.json` 为 null）；实现能量/技能三分类/换人/4 命的确定性结算；固定种子重放 | 1,000 场自动对局零非法动作，重放哈希 100% 一致 |
| **S1** 反馈函数与度量 | **先能生成诊断文本，再谈优化** | `μ_f` 渲染器（§6）、启发式 Bot、无 Playbook 的 LLM Bot、Elo/α-rank、配对评测、`D_sel`/`D_test` | 人工抽检 50 份 `feedback_text` 均可定位到具体机制；LLM Bot 显著优于随机 |
| **S2** 信度分配 | 定位该改哪一回合 | 校准偏差标记 + 反事实回放 + 关键回合卡片 | 回放确认的错误决策中 ≥ 60% 同时被校准偏差标记（两信号一致性检验） |
| **S3** V_θ（档位 A） | 便宜的不确定性估计 | 特征工程 + 树模型 + 价值落差扫描 | 中局胜率预测 AUC ≥ 0.75；关键回合定位优于随机基线 |
| **S4** 内层闭环 | GEPA + SkillOpt 跑通 | 候选池、Pareto 选择、双分析师、有界编辑、两级门禁、被拒绝缓冲区 | 跑通一次「入池」+ 一次「晋级」+ 一次「拒绝」；提升在 `D_test` 复现 |
| **S5** 慢更新 | 长程一致性 | epoch 慢更新 + 受保护区 + Meta Playbook | 连续 3 epoch `D_test` 单调不降；关闭慢更新做 A/B 可复现 SkillOpt 报告的显著退化 |
| **S6** 防坍缩与记忆 | 真实强度 | 专职剥削者、历史回归门禁、Situation Memory + 归因修正、健康度看板 | Champion 对全部历史成员胜率 ≥ 45%；可利用性可度量且下降；记忆消融显示正收益 |
| **S7** 外层构筑 | 元游戏搜索 | 联赛 + 收益矩阵 + 元求解 + M5 模块 + L3 数值搜索 | 至少一轮 PSRO 产出新阵容入池并改变 `σ*` |
| **S8** 后验采样 | 成本换胜率 | SMC + 门控 + 成本核算 | 单位成本胜率优于同成本 Best-of-N；门控在饱和局面正确关闭 |
| **S9** 交替迭代 | 两层协同 | 坐标上升调度 | 连续 3 epoch 在 `D_test` 上单调提升，且外层与内层交替各贡献可归因的增益 |

**S0–S2 是硬前置**。v1 说的是「S0–S1 硬前置」，v2 把 S2 也划进去：在没有 `feedback_text` 和信度分配之前，GEPA 的反思器只能看到「输了」，那它退化成随机文本搜索。GEPA 的收益明确来自评估痕迹的丰富程度。

## 16. 关键决策记录

- **ADR-S1（不变）：学习成果外化，不微调基础模型。** 闭源权重不可动是给定条件。
- **ADR-S2（不变）：奖励只来自确定性引擎，禁止 LLM 自评。** 产生候选的模型不能同时是唯一评委；自博弈里 LLM 评委会与被评策略共同漂移。
- **ADR-S3（不变）：构筑与对战分层交替优化。** 拒绝端到端联合，代价是收敛慢但信号可归因。
- **ADR-S4（v2 新增）：候选池即自博弈种群。** 用 GEPA 的实例级 Pareto 前沿同时承担文本进化父代池与 PSRO 策略种群。理由：在自博弈中「实例」= 「对手」，Pareto 支配关系恰是策略支配关系。代价：`D_sel` 评测成本成为主要开销（§14）。
- **ADR-S5（v2 强化）：变异必须有界且过两级门禁。** 入池宽（保多样性）、晋级严（防漂移）、平手拒绝。依据 SkillOpt 消融：无界重写在三个基准上一致更差。
- **ADR-S6（v2 新增）：Playbook 拆成 5 个模块。** 使 GEPA 的模块轮询与 system-aware Merge 可用，并让每次编辑的归因范围收窄到单模块。
- **ADR-S7（v2 新增）：`V_θ` 默认走零梯度档位 A。** 只在 AUC 长期不达 0.75 时升级到小模型档位 B。依据：本游戏状态维度低，手工特征够用；且 AMC 消融显示纯 prompting 的价值估计不可靠，所以「完全无学习器」不是选项。
- **ADR-S8（v2 新增）：修正 MemRL 的奖励广播。** 用反事实回放的 `delta_winrate` 做逐条目归因，替代终局奖励的均匀广播。理由：MemRL 论文自承这是其信度分配弱点，而自博弈的巨量对局会放大该噪声。代价：需要反事实回放，故只对关键回合的被采纳记忆做精确归因。
- **ADR-S9（v2 新增）：SMC 必须门控，且排在 Playbook 之后。** 依据 AMC 的 GPT-5.1/TextCraft 反转（Best-of-15 0.889 vs AMC 0.790）：强先验饱和时 SMC 有害。
- **ADR-S10（不变）：数值优化交给代码，语义组合交给 LLM。** 努力值/性格/血脉搜索不走 LLM。

## 17. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **图鉴数据为空（当前状态）** | 整个方案无法启动 | S0 硬前置；先填最小可玩子集（~20 精灵 / 40 技能 / 完整 `effort_rules` 与 `bloodline_rules`） |
| `feedback_text` 质量不足 | GEPA 层退化为随机文本搜索 | S1 硬前置 + 人工抽检 50 份 + 消融验证（去掉机制说明只留胜负，验证分数下降） |
| `D_sel` 评测成本失控 | 优化预算被验证吃光 | 两级门禁的廉价门 + 动态子采样实例 + SPRT |
| Pareto 池坍缩到 1–2 成员 | 退化为朴素自博弈 | 前沿宽度告警 + 手工风格对手池兜底 + 反对称分量监控 |
| Playbook 膨胀 | 延迟上升、注意力稀释 | 硬 token 上限（单模块 800 / 合计 2,500）+ 有界编辑 + 定期压缩（压缩也过门禁） |
| 记忆库 `Q` 被噪声洗成随机 | 检索失效 | §9.4 的归因修正 + Forgetting Rate 监控 + `content_pack_digest` 隔离 |
| `V_θ` 与 Champion 共同漂移 | 关键回合定位与 SMC 权重同时失效 | 每 epoch 用新分布重训 + 用反事实回放交叉验证定位质量 |
| SMC 在饱和局面上有害 | 花钱变弱 | §10.2 的三条门控 + 持续对比同成本 Best-of-N |
| LLM 提议的配置违规 | 浪费评测预算 | 所有 L2 提议先过 schema + 努力值/血脉/技能池约束校验 |
| 规则引擎与真实游戏不一致 | 学到的策略在真实环境失效 | 引擎版本化 + 与真实对局的一致性抽样校验 |
| 前沿模型行为版本变化 | 历史结论失效 | 固定模型 ID 与参数进策略版本；模型升级触发全量重评 |
| 门禁集过拟合 | `D_sel` 涨 `D_test` 不涨 | 三集隔离 + 优化器只见分数不见实例 + `D_test` 季度换血 30% |

## 18. 启动前需确认的问题

前 8 条沿用 v1 §13（规则引擎自研或对接、能量机制细节、三类技能克制是否与元素/特性交互、换人是否消耗回合、4 条命与 6 只精灵的绑定关系、构筑是赛前一次性决定还是可中途调整、算力与 token 预算、Playbook 是否作为人类可读攻略产出）。

v2 新增 4 条：

9. **`skill.schema.json` 的 `category` 是 `physical|magic|status`，与任务描述的「攻击/防御/状态」三分类不一致**。防御类技能是编码在 `physical/magic` 里靠 `power = 0` 区分，还是需要 schema 增加枚举值？这直接决定克制矩阵怎么实现。
10. 嵌入模型的选择与可用性（Situation Memory 的检索依赖它）。若无法接受额外的嵌入服务，`z` 的检索可退化为纯 `struct` 字段的精确/近似匹配——请确认是否接受这个降级。
11. 优化器模型是否可与目标模型不同（例如目标 Fable 5、优化器用更强或更便宜的档位）？SkillOpt 的实测显示强优化器收益更大且不增加部署成本，但需要确认账号与合规上是否允许。
12. `D_test` 是否需要物理隔离（独立仓库或加密），以确保 CI 与优化循环都无法读取？

## 19. 一句话总结

**冻结的模型是先验；变强的是围绕它的四件外挂**——一份被 Pareto 前沿引导、有界编辑、严格门禁筛选过的多模块文本手册；一个按实际因果贡献更新效用的情节记忆库；一个零梯度的价值估计器；以及一套只在关键回合启用的后验重采样。其中前三件永久生效且零推理开销，第四件是显式的成本换胜率交易。奖励永远只来自确定性引擎的胜负事实。
