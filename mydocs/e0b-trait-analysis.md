## 4. 聚类与共性

**核心洞察：特性 = 一只精灵绑定的「常驻被动效果包」**——它与技能效果共用同一套效果原语和事件钩子，区别只在**触发方式**：

| 触发方式 | 占比 | 例子 |
|---|---|---|
| 条件常驻（被动判定） | 最大头（能力强化 188） | `HP低于50%时草系技能威力+20%`、`造成克制伤害后攻防速+20%` |
| 事件触发（钩子） | 大（入场 99 / 回合末 50 / 受到伤害 30 / 回合开始 8） | `入场时`、`回合结束时`、`受到致命伤害时` |
| 一次性（每场战斗 1 次） | 14 | `不死鸟：每场战斗1次，受到致命伤害时保留1血` |
| 常驻属性（无触发） | 少数 | `闪避率小幅提升` |

**两条共性**：
1. **特性与技能共享同一套效果原语**——`攻防速+20%`（属性增减益）、`回复2能量`（能量）、`敌方获得15层灼烧`（异常）、`保留1血`（保命）、`印记`（印记）——全是技能系统里同一批 Modifier。
2. **特性的「事件触发」与技能的「事件触发」是同一批钩子**——入场/回合末/受到伤害/回合开始，技能和特性挂的是同一个事件总线。

所以：**技能效果系统（效果模型 + 钩子系统）一旦建成，特性系统就是「把一组效果原语绑到 Unit 上、由钩子按触发方式调度」**，几乎零新增架构。

## 5. 实现思路

### 5.1 数据模型
```python
@dataclass(frozen=True)
class Trait:
    name: str
    effects: tuple[Effect, ...]        # 复用技能效果模型（四元组：Trigger/Target/Modifier/Params）
    once_per_battle: bool = False      # 每场战斗 1 次（不死鸟）
    used: bool = False                 # once 标志（跑在 Unit 的可变副本上）

# Unit 新增字段
class Unit:
    ...
    trait: Trait | None = None         # 进场时绑定
    marks: dict[str, int] = {}         # 印记（与技能共享）
    statuses: dict[str, StatusTick] = {}
```

### 5.2 触发方式 → 钩子映射
| 特性触发 | 钩子 |
|---|---|
| 条件常驻（HP<50%、克制后） | 在 `deal_damage` / `take_damage` / `damage_calc` 钩子里查条件 |
| 入场 / 返场 | `on_enter` 钩子 |
| 回合结束 / 开始 | `on_turn_end` / `on_turn_start` 钩子 |
| 受到伤害 / 致命 | `on_take_damage`（致命=伤害后 HP 归零前拦截，`不死鸟` 的保命就在这） |
| 一次性 | `once_per_battle` 标志，首次触发后置 `used=True`（随 `to_dict` 序列化） |

### 5.3 关键实现点
- **「造成克制伤害后」依赖克制表**（E2 才有）——特性系统的这个子集要等克制表落地。
- **「受到致命伤害时保留1血」**：需要把 `apply_hp_loss` 的「归零置 faint」改成可拦截点（先扣血、若归零则跑 `on_fatal` 钩子，钩子可把 HP 改回 1 并取消 faint）。这正好挂在伤害漏斗 `apply_hp_loss` 上，不动漏斗形状。
- **「替换首个技能」**（圣光迪莫的裁决）：技能实例化（SkillInstance）后，特性可以改写某个技能槽——依赖 P1 的 SkillInstance。
- **「闪避率」**：需要命中/闪避判定——当前引擎无命中率，属于新机制（或暂不支持、登记为未覆盖）。

## 6. 与技能系统的关系（结论）

| 维度 | 技能 | 特性 |
|---|---|---|
| 消耗 | 行动 + 能量 | 无（被动） |
| 触发 | 使用技能（主动） | 条件 / 事件 / 一次性（被动） |
| 效果原语 | 同一套 | 同一套 |
| 事件钩子 | 同一批 | 同一批 |
| 状态依赖 | marks / statuses / weather | 读同一批 |

**因此：特性系统不增加架构复杂度，只增加一个 `Trait` 数据模型 + 一个 Unit 绑定 + 一个 once 标志。** 它的进度完全跟随技能效果系统的进度——技能效果能做多少，特性就能做多少。

## 7. 覆盖率预期

- 特性 593 条里，条件常驻（188）+ 能量（86）+ 异常（64）+ 回复（57）+ 印记（27）等**大头**都能落到「效果原语 + 钩子」上。
- 少数依赖新机制（闪避/命中、克制表 STAB）的会先登记为「未支持」，随 E2（克制表）补齐。
- 每阶段同样以「可表达特性数 / 总数」为可见指标。
