## 0. 结论速览

- **萌化结算已落地**：`stat="萌化"` 层数 = 沿进化链退阶数；实际资质已最低阶 → 施加
  拦截；解除 x 层沿链回升；特性/名字/技能不变；HP 同比例缩放（下限 1）。
- **「获得萌化：X」语义（2026-08-30 澄清）**：= 释放技能后**技能释放者 +1 层萌化
  （施加）**；施加成功（未达上限）→ 附加 X 效果；施加失败（实际资质已最低阶被拦截）
  → **无附加效果**。是「施萌化 + 条件附加」，**不是**「读萌化层数」的条件子句。
- **萌化相关技能 12 个**：已实现 1（**退化**，ST_EFFECTS「敌方获得N层萌化」模式），待实现 11。
- **萌化相关特性 7 个**：全部待实现。
  （另有两个 desc 含「资质」但实为**首领形态固有特性**——「国王的威严」「御驾亲征」，
  其「种族资质大幅增加」已体现在首领形态数据本身，与萌化机制无关，**不列入**。）
- 施工排序按**「复用现有原语程度」**分三档；同一档内按改动面从小到大排。

## 1. 萌化核心机制现状（能力边界）

### 1.1 已具备（可直接复用）

| 能力 | 落点 |
|---|---|
| 施加萌化层 | `AddModifier(萌化, special)` + ST 编译模式（「敌方获得N层萌化」，退化技能已通） |
| 萌化结算 | `reducer._recalc_morph`（层数夹 [0, 最大可退阶数]、退化/回升重算 `calc_combat_stats`）+ 最低阶施加拦截 |
| 萌化层数读取 | `statuses.morph_layers(unit)`（首领化门控已用） |
| 进化链索引 | `evolution.prev_of` / `prev_name_of` / `is_lowest` / `base_stats_of`（退化方向唯一、夹最低阶） |
| HP 同比例缩放 | `damage.apply_max_hp_change`（current_hp/max_hp 唯一写点漏斗） |
| 应对威力乘子 / 应对额外层数 | `SkillEffect.counter_damage_mult` / `counter_extra_layers` |
| 防御应对施印记 | `SkillEffect.counter_mark_effects`（捧杀可仿此泛化） |
| 读钩子模式 | `marks` 的 power_pct/power_flat/cost/speed、`weather` 的 power_multiplier/cost_halved |
| 特性触发（SKILL_RESOLVE） | `traits.TRAIT_CATALOG` + `triggers._trait_atoms` |
| 入场触发通道 | `UnitEntered` 领域事件（含 `from_boss`，棘刺/降灵已接线） |

### 1.2 缺失（待建 infra，是排序难度的主要分水岭）

| 编号 | 缺失能力 | 用途 |
|---|---|---|
| A | **读「自己/敌方萌化层数」→ 威力/能耗/连击数** 的读钩子 | 拆礼物 / 自由飘 / 月光合奏 / 蹦跶 |
| B | **应对施「状态」**（`counter_mark_effects` 泛化为施纯负面状态） | 捧杀（与冻结批 infra B 共用） |
| C | **萌化转移 / 主动解除**（移除自己萌化 → 施给敌方 / 直接解除） | 反弹 / 蹦跶 / 拉拉队长 |
| D | **「获得萌化：X」= 施萌化 + 条件附加**（释放者 +1 层萌化；施加成功 → 附加 X，最低阶拦截 → 无附加；编译时 `is_lowest` 检查或新「条件原子」） | 超级糖果 / 示弱 / 赤子之心 / 撒娇 / 甜心续航 |
| E | **特性触发扩展**（非 SKILL_RESOLVE：致命伤害 / 入场 / 离场 / 防御应对）+ source 守卫 | 化茧 / 守护者 / 迎宾 / 守望者 |
| F | **萌化层数上限豁免**（`_morph_max_layers` 夹取对特定特性放行） | 无忧无虑 |
| G | **永久属性/能耗变化**（`permanent=True` 层，离场不清除） | 示弱 / 赤子之心 / 撒娇 |

## 5. 关键风险 / 注意事项

1. **萌化与首领化的门控联动**：萌化层数 > 0 → 不可首领化（已实装）。反弹（转移）/
   蹦跶（解除）会改变萌化层数 → 首领化可用性随之变化，测试需覆盖「转移后对方萌化、
   自己解禁」的联动。
2. **「获得萌化：X」= 施萌化 + 条件附加**（2026-08-30 澄清）：超级糖果/示弱/赤子之心/
   撒娇/甜心续航 的 desc 里「自己获得萌化：X」= **先给释放者 +1 层萌化（施加），施加
   成功才附加 X**；实际资质已最低阶（达上限）被拦截 → **无附加效果**。编译时必须与
   「若敌方有萌化」（读层数条件，拆礼物）严格区分——前者是施加链（成功才附加），
   后者是读钩子（层数 > 0 即生效）；「本次威力+60」类附加要求**施萌化排在伤害前**结算。
3. **转移/解除的层数夹取**：反弹把萌化转移给敌方时，敌方可能是链最低阶（拦截）；
   解除萌化（蹦跶）在自己已是 0 层时是 no-op——都走既有 `_recalc_morph` 夹取兜底。
4. **无忧无虑的豁免范围**：「萌化层数不受限制」= `_morph_max_layers` 夹取豁免——
   层数可以超过链位置（资质夹到最低阶后继续叠层，只影响层数计数）；首领化门控
   （萌化>0 不可首领化）**仍然生效**，需在测试里钉死。
5. **化茧的致命伤害免伤是独立大机制**：涉及 `apply_hp_loss` 漏斗的伤害拦截（免伤）、
   一次伤害多次触发判定（连击内每段？）与 kwargs 计数重置——不应被化茧一个特性绑架，
   建议单独立项，先落「最多触发2次」的 kwargs 状态框架。
6. **迎宾/守护者的队伍级读钩子**：读「队伍中所有精灵的萌化层」跨单位聚合——现有
   读钩子都是单单位，需要新开队伍级聚合入口（类似 `marks._layers` 但按队伍）。
